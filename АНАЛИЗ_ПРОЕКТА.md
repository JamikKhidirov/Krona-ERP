# ПОЛНЫЙ АНАЛИЗ ПРОЕКТА KronaERP

## 1. ОБЩАЯ ИНФОРМАЦИЯ

**Название:** KronaERP
**Тип:** Мобильное Android-приложение для учёта заказов мебельной фабрики
**Язык:** Kotlin 2.0.21
**UI:** Jetpack Compose + Material 3
**Архитектура:** Multi-module MVVM + Repository + Hilt DI
**Бэкенд:** Firebase (Auth, Firestore, Storage)
**Навигация:** Navigation Compose 2.9.8 + Kotlin Serialization (type-safe routes)
**Минимальная версия:** Android 7.0 (API 24)
**Таргет:** Android 15 (API 36)
**Gradle:** 8.13, AGP 8.7.3, Kotlin DSL
**Пакет:** com.example.kronaerp
**Деплой:** Play Market (AAB)

**AuthViewModel.kt**
```kotlin
@HiltViewModel
class AuthViewModel @Inject constructor(
    private val authRepository: AuthRepository
) : ViewModel() {
    private val _authState = MutableStateFlow<AuthState>(AuthState.Idle)
    val authState: StateFlow<AuthState> = _authState.asStateFlow()
    
    init { checkAuthState() }
    
    fun registerUser(lastName, firstName, middleName, phone, email, password, role, adminCode = "") {
        viewModelScope.launch {
            _authState.value = AuthState.Loading
            val result = authRepository.registerUser(...)
            _authState.value = result.fold(
                onSuccess = { AuthState.Authenticated(it.role) },
                onFailure = { AuthState.Error(it.message ?: "Ошибка регистрации") }
            )
        }
    }
    
    fun signIn(email, password) {
        viewModelScope.launch {
            _authState.value = AuthState.Loading
            val result = authRepository.signIn(email, password)
            _authState.value = result.fold(
                onSuccess = { AuthState.Authenticated(it.role) },
                onFailure = { AuthState.Error(it.message ?: "Ошибка входа") }
            )
        }
    }
    
    fun logout() { authRepository.logout() }
    
    private fun checkAuthState() {
        if (authRepository.isUserAuthenticated()) {
            viewModelScope.launch {
                val profile = authRepository.getCurrentUserProfile().first()
                _authState.value = AuthState.Authenticated(profile?.role ?: "Клиент")
            }
        } else {
            _authState.value = AuthState.Idle
        }
    }
}
```

        if (currentUser == null) {
            _navigationState.value = NavigationState.Auth
        } else {

                firestore.collection("users").document(currentUser.uid).get()
                    .addOnSuccessListener { doc ->
                        val role = doc.getString("role") ?: "Клиент"
                        _navigationState.value = when (role) {
                            "Менеджер" -> NavigationState.Manager
                            else -> NavigationState.Client
                        }
                    }
                    .addOnFailureListener { _navigationState.value = NavigationState.Auth }
            }
        }
    }
}

## 6. ПОТОК ДАННЫХ (DATA FLOW)

```
Пользовательский ввод -> Composable (View)
  -> ViewModel (StateFlow/collectAsState)
    -> Repository (callbackFlow -> Firestore snapshot listener)
      -> Firebase Firestore (реальная БД)
    <- Repository эмитит Flow<List<T>>
  <- ViewModel обновляет StateFlow
<- Compose перерисовывается
```

**Жизненный цикл экрана:**
1. Composable вызывает hiltViewModel() для получения ViewModel
2. LaunchedEffect(Unit) вызывает viewModel.loadData()
3. ViewModel запускает корутину, подписывается на repository.getData()
4. Repository создаёт callbackFlow, подписывается на Firestore snapshot listener
5. Firestore шлёт обновления -> Repository конвертирует -> Flow эмитит
6. ViewModel получает, сохраняет в StateFlow
7. Compose перерисовывается через collectAsStateWithLifecycle()

## 7. ИЗВЕСТНЫЕ ПРОБЛЕМЫ (БАГИ)

1. **ClientGraph.kt ссылается на ManagerDestinations** — строка `navController.navigate(ManagerDestinations.OrderDetailScreenDestination(order))` должна быть `ClientDestinations.OrderDetailScreenDestinations(order.id)`

2. **ManagerGraph.kt** — `composable<ManagerDestinations.OrderDetailScreenDestination>` находится вне `navigation<ManagerGraphDestinaion>` блока (нарушена вложенность фигурных скобок)

3. **ТРИ дублирующиеся модели Order** — client/data/order/Order.kt, manager/data/Order.kt, orderdetailscreen/data/Order.kt (с разным набором полей)

4. **Два AuthRepository** — feature/auth (рабочий) и core/network (AuthRepositoryR — не используется)

5. **StatusConfig рассинхронизирован** — в manager версии нет поля dotColor, в client версии есть

6. **ManagerOrdersRepository.getAllOrders()** — при ошибке Firestore возвращает `trySend(emptyList())` вместо `close(error)`

7. **MyOrdersScreen** импортирует OrderViewModel из `neworder/viewmodels/` — архитектурно нелогично (ViewModel лежит в пакете neworder, но используется в myorders)

8. **Нет unit-тестов** — только заглушки

## 13. FIRESTORE ИНДЕКСЫ (нужны для работы запросов)

Для `firestore.collection("orders").whereEqualTo("userId", X).orderBy("createdAt", DESC)` нужен составной индекс:
- Collection: orders
- Fields: userId ASC, createdAt DESC

Для `firestore.collection("orders").whereEqualTo("assignedTo", X)` нужен индекс:
- Collection: orders
- Fields: assignedTo ASC

Остальные запросы не требуют индексов.
