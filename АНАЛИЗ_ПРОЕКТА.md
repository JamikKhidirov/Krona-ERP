# ПОЛНЫЙ АНАЛИЗ ПРОЕКТА KronaERP

## 1. ОБЩАЯ ИНФОРМАЦИЯ

**Название:** KronaERP
**Тип:** Мобильное Android-приложение для учёта заказов мебельной фабрики
**Язык:** Kotlin 2.0.21
**UI:** Jetpack Compose + Material 3
**Архитектура:** Multi-module MVVM + Repository + Hilt DI
**Бэкенд:** Firebase (Auth, Firestore, Storage, Cloud Messaging)
**Навигация:** Navigation Compose 2.9.8 + Kotlin Serialization (type-safe routes)
**Минимальная версия:** Android 7.0 (API 24)
**Таргет:** Android 15 (API 36)
**Gradle:** 8.13, AGP 8.7.3, Kotlin DSL
**Пакет:** com.example.kronaerp
**Деплой:** Play Market (AAB)

---

## 2. МОДУЛЬНАЯ СТРУКТУРА (7 модулей)

```
settings.gradle.kts регистрирует:
  :app
  :core:network
  :core:uikit
  :feature:auth
  :feature:client
  :feature:manager
  :feature:navigation
```

### 2.1 :app — Главный модуль (application)

**Точка входа:**
- `KronaApp.kt` — `@HiltAndroidApp`, инициализирует Firebase в `onCreate()`
- `MainActivity.kt` — `@AndroidEntryPoint`, SplashScreen API (1.5 сек), внутри `KronaAppNavigation()`

**Тема:**
- `ui/theme/Color.kt` — PrimaryBlue=0xFF25326A, SecondaryBlue=0xFF4A5E9A, GoldAccent=0xFFD4AF37
- `ui/theme/Theme.kt` — KronaERPTheme(darkTheme, dynamicColor, content)
  - LightColorScheme: primary=PrimaryBlue, background=#F5F7FA
  - DarkColorScheme: primary=#7C8FD4, background=#1A1C2E
  - Поддержка Android 12+ Dynamic Colors
- `ui/theme/Type.kt` — базовая Typography с кастомным bodyLarge

### 2.2 :core:network — Сетевой слой (library)

Hilt-модули:
- `AuthModule.kt` — `@Singleton FirebaseAuth`
- `ClientModule.kt` — `@Singleton FirebaseFirestore`, `@Singleton FirebaseStorage`

Модели:
- `UserProfile.kt` — data class: id, email, lastName, firstName, middleName, phone, address, role, createdAt, fcmToken
- `ClientRegistrationData.kt` — registration DTO с полями + adminCode
- `OrderStatus.kt` — enum: PENDING, ASSIGNED, IN_PROGRESS, READY, DELIVERING, COMPLETED, PAID, CANCELLED

### 2.3 :core:uikit — Общие UI-компоненты (library)

Общие модели:
- `Client.kt` — data class: id, lastName, firstName, middleName, phone, email, address, avatarUrl, role, activeOrdersCount, totalOrdersCount, createdAt, notes

Типобезопасные маршруты (навигация):
- `ClientDestinations.kt` — sealed interface:
  - `ClientGraph`, `MyOrdersScreenDestination`, `NewOrderScreenDestinations`, `ProfileScreenDestination`
  - `OrderDetailScreenDestinations(orderId)`, `ChatListScreenDestination`
  - `ChatThreadDestination(chatId, orderId)`, `AuthDestinationRelogin`

Общие компоненты:
- `ClientBottomNavigation.kt` — 3 вкладки: Мои заказы, Новый заказ, Профиль

Экран профиля (общий для клиента и менеджера):
- `MyProfileScreen.kt` — содержит:
  - MyProfileHeader (аватар, ФИО, роль, кнопка редактирования)
  - MyStatisticsCard (кол-во заказов: всего, активных, потрачено)
  - MyContactsCard (телефон, email, UID)
  - SettingsSection (настройки)
  - DangerZone (выход, удаление аккаунта)
- `MyProfileViewModel.kt` — `@HiltViewModel`, загружает профиль из Firestore, управляет logout/delete

UI-компоненты профиля:
- AddressCard, ContactRow, DangerZone, DeleteAccountDialog, EditProfileDialog
- EmptyState, LogoutConfirmDialog, MyContactsCard, MyProfileHeader
- MyStatisticsCard, SettingsItem, SettingsSection, StatItem

### 2.4 :feature:auth — Модуль аутентификации (library)

**Экраны:**
- `LogInScreen.kt` — email + password, кнопка входа с анимацией, ссылка на регистрацию
- `RegisterScreen.kt` — lastName, firstName, middleName, phone, address, email, password, role dropdown (Клиент/Менеджер), adminCode="admin787898" для менеджера

**ViewModel:**
- `AuthViewModel.kt` — `@HiltViewModel`

  - Методы: registerUser(), signIn(), logout(), checkAuthState()

**Repository:**
- `AuthRepository.kt` — @Singleton
  - signIn(): FirebaseAuth + Firestore чтение users/{uid}
  - registerUser(): FirebaseAuth createUser + Firestore запись
  - logout(), getCurrentUserProfile(): Flow через snapshot listener

## 9. НАВИГАЦИЯ

```
KronaAppNavigation (читает navigationState из AppNavigationViewModel)
  ├── Loading -> CircularProgressIndicator
  ├── Auth -> AuthGraph (LogInScreen <-> RegisterScreen)
  ├── Client -> ClientGraph
  │   ├── MyOrdersScreen -> OrderDetailScreen(orderId)
  │   ├── NewOrderScreen
  │   ├── ChatListScreen -> ChatThread(chatId, orderId)
  │   └── ProfileScreen
  └── Manager -> ManagerGraph
      ├── DashboardScreen
      ├── ClientsScreen -> UserDetailScreen(clientId)
      ├── OrdersScreen -> OrderDetailScreen(orderId)
      ├── StatisticsScreen
      ├── ChatListScreen -> ChatThread(chatId, orderId)
      └── ProfileScreen
```

**AppNavigationViewModel:** проверяет FirebaseAuth.currentUser -> Firestore users/{uid}.role -> NavigationState
**Типобезопасные маршруты:** sealed interface + @Serializable, маршруты в ClientDestinations и ManagerDestinations
