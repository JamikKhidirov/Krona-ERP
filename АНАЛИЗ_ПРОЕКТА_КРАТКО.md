# KronaERP — ПОЛНЫЙ АНАЛИЗ ПРОЕКТА (ДЛЯ НЕЙРОСЕТИ)

## 1. ОБЩЕЕ

**Тема:** Android-приложение учёта заказов мебельной фабрики
**Стек:** Kotlin 2.0.21, Jetpack Compose + Material3, Dagger Hilt 2.57.1, Firebase (Auth, Firestore, Storage), Navigation Compose 2.9.8 + Kotlin Serialization
**Архитектура:** Multi-module MVVM + Repository + Hilt DI
**Min SDK:** 24, **Target:** 36
**Пакет:** com.example.kronaerp

---

## 2. МОДУЛИ (7 шт)

| Модуль | Тип | Назначение |
|--------|-----|-----------|
| `:app` | application | Точка входа, тема, ресурсы. MainActivity + KronaApp(HiltAndroidApp) |
| `:core:network` | library | Firebase DI модули (FirebaseAuth, FirebaseFirestore, FirebaseStorage), модель UserProfile, OrderStatus enum |

| `:feature:manager` | library | ManagerOrdersScreen, ClientsScreen, UserDetailScreen, ManagerOrdersViewModel, ClientsViewModel, UserDetailViewModel, ManagerOrdersRepository, ClientRepository |
| `:feature:navigation` | library | AppNavigationViewModel, KronaAppNavigation, KronaNavHost, AuthGraph, ClientGraph, ManagerGraph, все sealed маршруты |

## 4. ВСЕ МОДЕЛИ

**OrderStatus enum:** PENDING, ASSIGNED, IN_PROGRESS, READY, DELIVERING, COMPLETED, CANCELLED

**Order (client & manager — идентичны):**
- id, userId, clientName, clientPhone, productType, description, height, width, length
- budget, advancePayment, status, createdAt, updatedAt, assignedTo, hasPhotos
- comment, masterComment, materialCost, additionalCosts
- computed: profit (budget - advancePayment - materialCost - additionalCosts), isComplete, isCancelled, isActive

**GetOrder (облегчённая для списка):** id, userId, clientName, productType, budget, status, createdAt

**OrderDetail (для OrderDetailScreen — упрощённая):** без assignedToName, с profit

**ProductType enum:** CABINET(Шкаф), TABLE(Стол), BED(Кровать), CHAIR(Стул), SHELF(Полка), SOFA(Диван), OTHER(Другое)

**Client:** id, lastName, firstName, middleName, phone, email, address, avatarUrl, role, activeOrdersCount, totalOrdersCount, createdAt, notes

**OrderFilter enum:** ALL, NEW, ASSIGNED, IN_PROGRESS, READY, DELIVERING, COMPLETED, CANCELLED, UNASSIGNED, MY_ORDERS

## 5. ВСЕ ЭКРАНЫ (9 шт)

### 5.1 Auth

- **LogInScreen** — email + password, кнопка "Войти" (AuthButton с scale анимацией), ссылка "Зарегистрироваться". AuthViewModel.signIn()
- **RegisterScreen** — lastName, firstName, middleName, phone, address, email, password, confirmPassword, role dropdown (Клиент/Менеджер), adminCode="admin787898" для менеджера. AuthViewModel.registerUser()

### 5.2 Client

- **MyOrdersScreen** — LazyColumn с OrderCard (иконка productType, название, бюджет, StatusChip), сверху OrdersStatistics (кол-во: всего/активных/PENDING/COMPLETED), Loading/Empty/Error состояния. ClientBottomNavigation
- **NewOrderScreen** — ProductType grid (2 колонки, 7 типов), DimensionsSection (width/height/length числовые поля), CommentSection (multiline), PhotoUploadSection (до 5 фото, выбор из галереи), Submit кнопка. OrderViewModel.createOrder()
- **OrderDetailScreen** — OrderHeader + OrderPhotos + CharacteristicsSection + FinanceSection + MasterCard + StatusTimeline + DocumentsSection + CommentSection. OrderDetailViewModel.loadOrder()

### 5.3 Manager

- **ManagerOrdersScreen** — FilterChips (10 фильтров), LazyColumn ManagerOrderCard (клиент, тип, статус, бюджет, кнопки Assign/Call/Status). ManagerBottomNavigation. ManagerOrdersViewModel с combine(all, unassigned, my orders)
- **ClientsScreen** — SearchBar (поиск по имени/телефону/email), LazyColumn ClientCard (аватар, ФИО, телефон, кол-во заказов). ClientsViewModel
- **UserDetailScreen** — ProfileHeader + ContactInfoCard + ClientStatisticsCard + RegistrationDateCard + UidCard + NotesCard + список заказов клиента. UserDetailViewModel

### 5.4 Общие

- **MyProfileScreen** (core:uikit) — MyProfileHeader + MyStatisticsCard + MyContactsCard + SettingsSection + DangerZone (logout/delete). MyProfileViewModel (Firebase Auth + Firestore)

## 8. НАВИГАЦИЯ

```
KronaAppNavigation (читает navigationState)
  ├── Loading -> CircularProgressIndicator
  ├── Auth -> AuthGraph (LogInScreen <-> RegisterScreen)
  ├── Client -> ClientGraph (MyOrders -> OrderDetail, NewOrder, Profile)
  └── Manager -> ManagerGraph (Clients -> UserDetail, Orders -> OrderDetail, Profile)
```

**AppNavigationViewModel:** проверяет FirebaseAuth.currentUser -> Firestore users/{uid}.role -> NavigationState
**Типобезопасные маршруты:** sealed interface + @Serializable, маршруты в ClientDestinations и ManagerDestinations

## 10. ИЗВЕСТНЫЕ ПРОБЛЕМЫ

1. **ClientGraph.kt** использует `ManagerDestinations.OrderDetailScreenDestination` вместо `ClientDestinations.OrderDetailScreenDestinations` (2 места)
2. **ManagerGraph.kt** — `composable<OrderDetailScreenDestination>` вне navigation-блока (нарушены скобки)
3. **Три Order data class** — client/data/order/Order.kt, manager/data/Order.kt (идентичны), orderdetail/data/Order.kt (упрощённая)
4. **Два AuthRepository** — feature/auth (рабочий) и core/network/AuthRepositoryR (не используется)
5. **StatusConfig** — в manager без dotColor, в client с dotColor
6. **ManagerOrdersRepository.getAllOrders()** — при ошибке возвращает emptyList вместо close(error)
