# Глава 2. Проектирование и разработка приложения

## 2.1. Постановка задач и функциональные требования

### 2.1.1. Анализ предметной области

Мебельная фабрика представляет собой предприятие, занимающееся производством и реализацией мебельной продукции на заказ. В рамках своей деятельности фабрика взаимодействует с двумя основными категориями пользователей: клиентами (заказчиками) и менеджерами (сотрудниками фабрики). Каждая категория имеет свои уникальные потребности и сценарии использования программного обеспечения.

Традиционно учёт заказов на мебельных производствах осуществляется с использованием бумажной документации, электронных таблиц или разрозненных программных решений, что приводит к ряду проблем: задержки в обработке заявок, потеря данных, отсутствие прозрачности статуса заказа для клиента, сложность отслеживания истории взаимодействия с заказчиками. Разработка специализированного мобильного приложения призвана решить перечисленные проблемы путём автоматизации ключевых бизнес-процессов фабрики.

### 2.1.2. Функциональные требования к системе

На основе анализа предметной области были сформулированы функциональные требования, разделённые по категориям пользователей.

**Требования для клиента (заказчика):**
- Регистрация в системе и авторизация с использованием адреса электронной почты и пароля.
- Просмотр списка собственных заказов с отображением текущего статуса каждого заказа.
- Создание нового заказа с указанием типа изделия, габаритных размеров, комментариев и загрузкой фотографий-референсов.
- Просмотр детальной информации по конкретному заказу, включая историю изменения статусов.
- Просмотр и редактирование профиля пользователя, включая контактные данные и адрес доставки.

**Требования для менеджера (сотрудника фабрики):**
- Авторизация в системе с использованием специального кода доступа при регистрации.
- Просмотр списка всех заказов с возможностью фильтрации по статусу.
- Просмотр списка клиентов с возможностью поиска по имени, телефону или email.
- Просмотр детальной информации о клиенте, включая историю его заказов.
- Назначение заказа на конкретного мастера или исполнителя.
- Изменение статуса заказа по мере его выполнения.
- Просмотр аналитической информации в профиле пользователя.

**Общие требования:**
- Аутентификация и авторизация всех пользователей.
- Защита персональных данных пользователей.
- Синхронизация данных в реальном времени.
- Поддержка тёмной и светлой темы оформления.

### 2.1.4. Нефункциональные требования

Помимо функциональных требований, к системе предъявляются следующие нефункциональные требования:

- **Производительность:** время отклика интерфейса не должно превышать 300 мс при выполнении стандартных операций.
- **Масштабируемость:** архитектура должна поддерживать возможность добавления новых модулей и функциональности без существенной переработки существующего кода.
- **Надёжность:** система должна корректно обрабатывать ошибки сети и отображать понятные пользователю сообщения.
- **Безопасность:** аутентификация должна осуществляться через Firebase Authentication; передача данных — по защищённому протоколу HTTPS.
- **Поддержка устройств:** приложение должно функционировать на устройствах с Android 7.0 (API 24) и выше.

## 2.3. Выбор технологического стека и средств разработки

### 2.3.1. Язык программирования — Kotlin

Kotlin является официальным языком разработки для Android, начиная с Google I/O 2019. Выбор Kotlin обусловлен следующими преимуществами:
- **Полная совместимость с Java** — возможность использования всех существующих Java-библиотек.
- **Null-безопасность** — встроенная система типов, предотвращающая ошибки, связанные с null-значениями.
- **Coroutines** — встроенная поддержка асинхронного программирования через корутины.
- **Extension-функции** — возможность расширения существующих классов без наследования.
- **Data-классы** — лаконичный синтаксис для создания моделей данных с автоматической генерацией equals(), hashCode(), toString().

### 2.3.2. Средства разработки пользовательского интерфейса — Jetpack Compose

Jetpack Compose — современный декларативный UI-фреймворк для Android, основанный на composable-функциях. В отличие от традиционного подхода на основе XML-разметки, Jetpack Compose позволяет описывать интерфейс непосредственно в Kotlin-коде, что обеспечивает:

- **Декларативный подход** — описание того, как интерфейс должен выглядеть при заданном состоянии, а не последовательности шагов по его изменению.
- **Реактивность** — автоматическое обновление интерфейса при изменении состояния.
- **Меньше кода** — сокращение объёма кода по сравнению с XML-разметкой в среднем на 30-40%.

### 2.3.3. Внедрение зависимостей — Dagger Hilt

Hilt — библиотека внедрения зависимостей для Android, построенная поверх Dagger. Она упрощает настройку DI и предоставляет:
- Стандартные компоненты (Application, Activity, Fragment, ViewModel, Service).
- Аннотации `@HiltViewModel`, `@AndroidEntryPoint`, `@Singleton`, `@Provides`, `@Binds`.

suspend fun signIn(
    email: String,
    password: String
): Result<UserProfile> = withContext(Dispatchers.IO) {
    try {
        val result = auth.signInWithEmailAndPassword(email, password)
        val uid = result.user?.uid ?: return@withContext Result.failure(Exception("UID is null"))
        val document = firestore.collection("users").document(uid).get().await()
        val profile = document.toObject<UserProfile>()
            ?: return@withContext Result.failure(Exception("User not found"))
        Result.success(profile)
    } catch (e: Exception) {
        Result.failure(e)
    }
}
```

fun getUserOrders(userId: String): Flow<List<Order>> = callbackFlow {
    val listener = firestore.collection("orders")
        .whereEqualTo("userId", userId)
        .orderBy("createdAt", Query.Direction.DESCENDING)
        .addSnapshotListener { snapshot, error ->
            if (error != null) {
                close(error)
                return@addSnapshotListener
            }
            val orders = snapshot?.documents?.mapNotNull { doc ->
                doc.toObject(Order::class.java)?.copy(id = doc.id)
            } ?: emptyList()
            trySend(orders)
        }
    awaitClose { listener.remove() }
}
```

Код для вставки (файл `feature/auth/src/main/java/com/example/auth/screens/register/viewmodel/AuthViewModel.kt`):
```kotlin
sealed class AuthState {
    data object Idle : AuthState()
    data object Loading : AuthState()
    data object Authenticated : AuthState()
    data class Error(val message: String) : AuthState()
}

@HiltViewModel
class AuthViewModel @Inject constructor(
    private val authRepository: AuthRepository
) : ViewModel() {

    private val _authState = MutableStateFlow<AuthState>(AuthState.Idle)
    val authState: StateFlow<AuthState> = _authState.asStateFlow()

    fun registerUser(
        lastName: String,
        firstName: String,
        middleName: String,
        phone: String,
        email: String,
        password: String,
        role: String,
        adminCode: String = ""
    ) {
        viewModelScope.launch {
            _authState.value = AuthState.Loading
            val result = authRepository.registerUser(
                lastName, firstName, middleName, phone,
                email, password, role, adminCode
            )
            _authState.value = result.fold(
                onSuccess = { AuthState.Authenticated },
                onFailure = { AuthState.Error(it.message ?: "Ошибка регистрации") }
            )
        }
    }

    fun signIn(email: String, password: String) {
        viewModelScope.launch {
            _authState.value = AuthState.Loading
            val result = authRepository.signIn(email, password)
            _authState.value = result.fold(
                onSuccess = { AuthState.Authenticated },
                onFailure = { AuthState.Error(it.message ?: "Ошибка входа") }
            )
        }
    }
}
```
